# 💍 تجهيزات عرس أخوي

تطبيق ويب شخصي (Wedding Planner) لمتابعة كل تجهيزات العرس: المهام، الميزانية، المسؤولين، الجدول الزمني ليوم العرس، وشنطة الطوارئ — بدون تسجيل دخول وبدون أي كود Backend خاص بك. البيانات تُحفظ افتراضيًا في متصفحك (LocalStorage)، ويمكن ربطها اختياريًا بمشروع Firebase مجاني (خطوات أدناه) لتصبح محفوظة على السحابة ومتزامنة لحظيًا بين كل من يفتح موقعك.

## 📁 هيكل الملفات

```
wedding-planner/
├── index.html                 # الصفحة الرئيسية (كل التبويبات والمودال)
├── assets/
│   ├── css/
│   │   └── style.css          # كل التصميم: الألوان، الخطوط، RTL، الحركات، الطباعة
│   └── js/
│       ├── firebase-config.js # بيانات مشروع Firebase الخاص بك (فارغة افتراضيًا)
│       ├── data.js            # البيانات الافتراضية + طبقات التخزين (Firebase / LocalStorage)
│       ├── state.js           # إدارة الحالة + عمليات الإضافة/التعديل/الحذف + الحسابات
│       ├── render.js          # كل دوال رسم الواجهة لكل تبويب
│       └── app.js             # الربط بين الأحداث والواجهة + المودال + الاستيراد/التصدير
└── README.md
```

لا يوجد أي build step. المشروع HTML/CSS/JS عادي (Vanilla) — يعمل مباشرة بفتح `index.html` أو بأي استضافة ثابتة (Static Hosting).

## 🧠 كيف صُممت طبقة البيانات

كل قراءة/كتابة للبيانات تمر حصريًا من خلال Adapter موحّد الواجهة في [assets/js/data.js](assets/js/data.js):
```js
{ async getAll() {...}, async setAll(data) {...}, subscribe(onRemoteChange) {...} }
```
عند فتح الصفحة، يختار `AppState.load()` أول مصدر متاح بهذا الترتيب:

1. **Firebase** — إذا عبّأتِ [assets/js/firebase-config.js](assets/js/firebase-config.js) ببيانات مشروعك (هذا ما يجعل البيانات محفوظة ومتزامنة بين كل من يفتح موقعك الخاص).
2. **LocalStorage** — إذا لم يتوفر Firebase، تُحفظ البيانات على هذا الجهاز فقط ولا تختفي عند تحديث الصفحة (لكنها لا تتزامن مع أجهزة أخرى).

(عند تشغيل نفس الكود كـ Claude Artifact تحديدًا، يُستخدم أولًا مصدر مزامنة خاص بمنصة Claude — لا علاقة له بموقعك المستقل.)

## 🔥 الربط بـ Firebase (لحفظ ومزامنة البيانات على موقعك)

هذا يجعل بيانات تجهيزات العرس تُحفظ على السحابة وتظهر فورًا عند كل من يفتح موقعك — بدون أي تسجيل دخول لمن يفتحه. مجاني بالكامل لهذا الحجم من الاستخدام.

1. ادخلي [console.firebase.google.com](https://console.firebase.google.com) وسجّلي بحساب Google → **Add project** → اختاري اسمًا (مثلاً `wedding-samer`) → أكملي الإنشاء (يمكنك تعطيل Google Analytics، غير ضروري).
2. من القائمة الجانبية: **Build → Firestore Database** → **Create database** → اختاري وضع **Start in test mode** → اختاري أقرب موقع سيرفر → **Enable**.
3. بعد الإنشاء اذهبي لتبويب **Rules** داخل Firestore واستبدلي المحتوى بهذا (يسمح بالقراءة والكتابة على وثيقة تجهيزات العرس فقط، بدون تسجيل دخول):
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /weddingPlanner/sharedState {
         allow read, write: if true;
       }
     }
   }
   ```
   ثم اضغطي **Publish**.
4. ارجعي لصفحة المشروع الرئيسية (⚙️ **Project settings**) → أسفل **Your apps** اضغطي أيقونة الويب `</>` → سمّي التطبيق (مثلاً `wedding-site`) → **Register app**. ستظهر لك قيم `firebaseConfig`.
5. افتحي ملف [assets/js/firebase-config.js](assets/js/firebase-config.js) في مشروعك، واستبدلي:
   ```js
   const FIREBASE_CONFIG = null;
   ```
   بالقيم التي ظهرت لك، بنفس الشكل الموضّح في تعليق المثال أسفل الملف.
6. احفظي الملف وارفعي المشروع (أو حدّثيه) — ستلاحظين الشارة أعلى الصفحة تتحول إلى 🟢 "متزامن ومحفوظ على السحابة".

> ⚠️ بما أن الموقع بدون تسجيل دخول (حسب طلبك)، قواعد Firestore أعلاه مفتوحة لأي شخص يعرف رابط مشروعك تحديدًا (ليس رابط الموقع العادي) — مناسب لبيانات تجهيزات عرس شخصية، لكن لا تستخدمي نفس المشروع لبيانات حسّاسة أكثر من ذلك مستقبلًا.

## ▶️ خطوات التشغيل محليًا

**الطريقة الأسهل:** افتحي ملف `index.html` مباشرة بالمتصفح (دبل كلك عليه).

**أو عبر سيرفر محلي بسيط** (يعطي تجربة أقرب للاستضافة الحقيقية):

```bash
cd wedding-planner
python3 -m http.server 8080
```

ثم افتحي المتصفح على `http://localhost:8080`

أو باستخدام Node:
```bash
npx serve wedding-planner
```

## 🐙 خطوات رفعه على GitHub

```bash
cd wedding-planner
git init
git add .
git commit -m "تجهيزات عرس أخوي - النسخة الأولى"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO-NAME.git
git push -u origin main
```

### تفعيل GitHub Pages
1. ادخلي إلى المستودع على GitHub → **Settings** → **Pages**
2. من **Source** اختاري: **Deploy from a branch**
3. اختاري الفرع **main** والمجلد **/ (root)**
4. احفظي، وبعد دقيقة سيكون الموقع متاحًا على:
   `https://USERNAME.github.io/REPO-NAME/`

## ☁️ خطوات نشره على Cloudflare Pages

1. ادخلي على [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** → **Create application** → **Pages** → **Connect to Git**
2. اختاري مستودع GitHub الذي رفعتِ عليه المشروع
3. إعدادات البناء (Build settings):
   - **Framework preset:** None
   - **Build command:** (اتركيه فارغًا)
   - **Build output directory:** `/`
4. اضغطي **Save and Deploy**
5. بعد دقائق سيكون الموقع متاحًا على رابط مثل:
   `https://REPO-NAME.pages.dev`

> بما أن المشروع صفحة ثابتة بدون build step، لا حاجة لأي إعدادات إضافية أو متغيرات بيئة (Environment Variables).

## ✅ الميزات المتوفرة فعليًا

- عد تنازلي حي لموعد الزواج
- لوحة إحصائيات (مهام + ميزانية) مع Progress Bar دائري وأفقي
- 7 أقسام تجهيزات مع 56 مهمة جاهزة مسبقًا
- إضافة / تعديل / حذف / نقل المهام بين الأقسام عبر نافذة تفاصيل كاملة
- حساب "المبلغ المتبقي" تلقائيًا لكل مهمة وللميزانية الكلية
- قسم "يحتاج انتباه" يعرض المهام المتأخرة/القريبة/غير المدفوعة تلقائيًا
- تبويب المسؤولين مع عداد مهام لكل شخص
- تبويب يوم العرس (Timeline) قابل للتعديل الكامل
- شنطة الطوارئ (Checklist) قابلة للتعديل
- بحث + فلاتر (الكل / المتبقي / المكتمل / العاجل / غير المدفوع / حسب المسؤول)
- تصدير/استيراد نسخة احتياطية JSON
- طباعة، مشاركة (Web Share API)، ونسخ المهام المتبقية كنص جاهز للواتساب
- Bottom Navigation على الجوال + Top Navigation على الشاشات الكبيرة
- كل البيانات محفوظة تلقائيًا في LocalStorage ولا تختفي عند تحديث الصفحة

## 🔒 الخصوصية

كل البيانات تبقى في متصفحك فقط على جهازك — لا يوجد أي إرسال لأي سيرفر خارجي. لأخذ نسخة احتياطية أو نقل البيانات لجهاز آخر استخدمي زر "تصدير نسخة احتياطية JSON" من تبويب "نسخ احتياطي".
